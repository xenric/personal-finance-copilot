# Domain Model Specification

## 1. 문서 목적

이 문서는 Personal Finance Copilot에서 사용하는 핵심 재무 개념과 관계를 정의한다.

다음 내용은 이 문서에서 다룬다.

- 시스템이 관리해야 하는 핵심 개념
- 각 개념의 역할과 책임
- 개념 사이의 관계
- 반드시 지켜야 하는 도메인 규칙

다음 내용은 별도 문서 또는 구현 단계에서 정의한다.

- JSON 파일의 구체적인 구조
- API 요청 및 응답 형식
- 클래스와 패키지 구조
- 화면 구성
- 재무 계산 공식
- 경고 임계값
- AI 프롬프트

---

## 2. 전체 구조

Personal Finance Copilot은 다음 구조로 재무 데이터를 관리한다.

```text
FinancialProfile
    │
    ├── CurrentFinancialState
    │       ├── Assets
    │       ├── Liabilities
    │       ├── MonthlyCashFlow
    │       └── FinancialGoals
    │
    └── Snapshots
            ├── FinancialMetrics
            ├── FinancialWarnings
            ├── PeriodComparison
            └── RecommendationOptions

ReviewReport
    └── Snapshot 참조
```

핵심 흐름은 다음과 같다.

```text
현재 재무 상태 입력
    ↓
재무 지표 계산
    ↓
재무 경고 생성
    ↓
스냅샷 저장
    ↓
이전 스냅샷과 비교
    ↓
AI 리뷰 보고서 생성
```

## 3. 공통 개념

### 3.1 Money

금액과 통화를 함께 표현한다.

예시:

```text
5,000,000 KRW
1,000 USD
```

Money는 다음 정보를 가진다.

| 항목     | 설명 |
| -------- | ---- |
| amount   | 금액 |
| currency | 통화 |

규칙:

- 금액과 통화는 항상 함께 관리한다.
- 서로 다른 통화는 환율 없이 직접 합산하지 않는다.
- 금액 계산은 정밀도가 보존되는 방식으로 처리한다.
- 저장 형식과 관계없이 도메인에서는 하나의 값으로 취급한다.

---

### 3.2 Percentage

비율을 표현한다.

사용 예시:

- 저축률
- 부채 비율
- 자산배분 비중
- 목표 자산배분
- 투자상품 집중도

규칙:

- 내부 표현 방식을 프로젝트 전체에서 통일한다.
- `15%`와 `0.15`를 혼용하지 않는다.
- 비율 변화와 퍼센트포인트 변화를 구분한다.

예시:

```text
기존 비중: 50%
현재 비중: 60%

변화: 10%p 증가
```

---

### 3.3 Period

재무 상태를 분석하는 기간을 표현한다.

MVP에서는 월 단위를 기본으로 한다.

예시:

```text
2026-07
2026-08
```

규칙:

- 동일한 형식으로 기간을 식별한다.
- 기간은 파일명, 스냅샷, 보고서에서 같은 기준을 사용한다.
- 기본 시간대는 `Asia/Seoul`이다.

## 4. FinancialProfile

### 정의

사용자의 재무 분석 기준과 기본 설정을 나타낸다.

FinancialProfile은 자산이나 부채 자체가 아니라, 재무 상태를 어떻게 분석할지 결정하는 기준이다.

### 주요 정보

| 항목                      | 설명                              |
| ------------------------- | --------------------------------- |
| baseCurrency              | 모든 분석 결과를 표시할 기준 통화 |
| investmentHorizon         | 예상 투자 기간                    |
| riskTolerance             | 사용자가 설정한 위험 성향         |
| emergencyFundTargetMonths | 목표 비상자금 개월 수             |
| targetAssetAllocation     | 목표 자산배분                     |

### 규칙

- 기준 통화는 반드시 존재해야 한다.
- 비상자금 목표 개월 수는 0보다 커야 한다.
- 목표 자산배분의 전체 합은 100%여야 한다.
- 위험 성향은 AI가 임의로 변경하지 않는다.
- 프로필 변경이 과거 스냅샷의 기준을 변경해서는 안 된다.

---

## 5. CurrentFinancialState

### 정의

현재 시점에서 사용자가 관리하는 재무 상태다.

현재 상태는 사용자가 자산이나 부채를 변경할 때마다 수정될 수 있다.

### 포함 정보

```text
CurrentFinancialState
 ├── Assets
 ├── Liabilities
 ├── MonthlyCashFlow
 └── FinancialGoals
```

### 주요 정보

| 항목        | 설명               |
| ----------- | ------------------ |
| asOfDate    | 현재 상태의 기준일 |
| assets      | 보유 자산          |
| liabilities | 보유 부채          |
| cashFlow    | 월 단위 현금흐름   |
| goals       | 재무 목표          |
| updatedAt   | 마지막 수정 시각   |

### 규칙

- 현재 재무 상태는 수정 가능하다.
- 현재 상태를 수정해도 과거 스냅샷은 변경되지 않는다.
- 모든 금액에는 통화가 있어야 한다.
- 모든 평가 금액에는 기준일이 있어야 한다.
- 입력 데이터가 유효하지 않으면 저장하지 않는다.

---

## 5.1 MonthlyCashFlow

### 정의

월 단위 현금흐름 계산에 필요한 소득, 지출, 상환액, 투자 가능 금액을 나타낸다.

### 주요 정보

| 항목                       | 설명                           |
| -------------------------- | ------------------------------ |
| monthlyIncome              | 세후 기준 월평균 소득          |
| monthlyFixedExpense        | 주거비, 보험료 등 고정지출     |
| monthlyVariableExpense     | 식비, 여가비 등 변동지출       |
| monthlyDebtPayment         | 월 부채 상환액                 |
| availableMonthlyInvestment | 정기적으로 투자할 수 있는 금액 |

### 규칙

- 각 금액은 `Money`로 관리한다.
- 소득과 지출은 음수가 될 수 없다.
- `monthlyDebtPayment`는 부채별 `monthlyPayment` 합계와 다를 수 있으며, 차이는 경고 근거로 사용할 수 있다.
- 월 저축액과 월 저축률은 이 모델의 값을 사용해 계산한다.

---

## 6. Asset

### 정의

사용자가 현재 소유하고 있으며 금전적 가치가 있는 항목이다.

현금, 예금, 부동산과 투자상품을 모두 Asset으로 관리한다.

### 자산 유형

| 유형        | 예시          |
| ----------- | ------------- |
| CASH        | 현금          |
| DEPOSIT     | 예금          |
| SAVINGS     | 적금          |
| STOCK       | 개별 주식     |
| ETF         | 국내·해외 ETF |
| BOND        | 채권          |
| GOLD        | 금            |
| REAL_ESTATE | 부동산        |
| OTHER       | 기타 자산     |

### 공통 정보

| 항목          | 설명                   |
| ------------- | ---------------------- |
| id            | 자산 식별자            |
| name          | 사용자에게 보여줄 이름 |
| type          | 자산 유형              |
| value         | 현재 평가금액          |
| valuationDate | 평가 기준일            |

### 투자자산 선택 정보

주식, ETF, 채권처럼 수량과 가격을 관리하는 자산은 다음 정보를 추가로 가질 수 있다.

| 항목                 | 설명           |
| -------------------- | -------------- |
| symbol               | 종목 코드      |
| quantity             | 보유 수량      |
| unitPrice            | 단위 가격      |
| averagePurchasePrice | 평균 매입 가격 |
| market               | 거래 시장      |

### 규칙

- 자산 식별자는 중복될 수 없다.
- 자산 평가금액은 기본적으로 음수가 될 수 없다.
- 자산 유형은 반드시 지정해야 한다.
- 투자자산의 평가금액은 수량과 가격으로 계산할 수 있다.
- 직접 입력한 평가금액과 계산한 평가금액을 동시에 사용할 경우 우선순위를 명확히 한다.
- 가격이나 환율이 없으면 임의의 값으로 대체하지 않는다.

---

## 7. Liability

### 정의

사용자가 미래에 상환해야 하는 금전적 의무다.

### 부채 유형

| 유형        | 예시         |
| ----------- | ------------ |
| MORTGAGE    | 주택담보대출 |
| CREDIT_LOAN | 신용대출     |
| AUTO_LOAN   | 자동차 대출  |
| CARD_DEBT   | 카드 부채    |
| OTHER       | 기타 부채    |

### 주요 정보

| 항목               | 설명             |
| ------------------ | ---------------- |
| id                 | 부채 식별자      |
| name               | 부채 이름        |
| type               | 부채 유형        |
| outstandingBalance | 현재 미상환 잔액 |
| interestRate       | 적용 금리        |
| valuationDate      | 잔액 기준일      |

### 선택 정보

| 항목           | 설명        |
| -------------- | ----------- |
| monthlyPayment | 월 상환금   |
| maturityDate   | 만기일      |
| institution    | 금융기관    |
| note           | 사용자 메모 |

### 규칙

- 부채 식별자는 중복될 수 없다.
- 미상환 잔액은 음수가 될 수 없다.
- 이자율의 단위를 일관되게 사용한다.
- 잔액이 0인 부채는 상환 완료 상태로 표시할 수 있다.
- 금리가 없는 부채는 고금리 부채 규칙을 평가할 수 없다.

---

## 8. FinancialGoal

### 정의

사용자가 달성하거나 유지하려는 재무 목표다.

### 목표 유형

| 유형                  | 설명                         |
| --------------------- | ---------------------------- |
| EMERGENCY_FUND        | 비상자금 확보                |
| NET_WORTH             | 목표 순자산 달성             |
| SAVINGS_RATE          | 목표 저축률 유지             |
| ASSET_ALLOCATION      | 목표 자산배분 유지           |
| DEBT_REDUCTION        | 목표 부채 수준 달성          |
| TARGET_AMOUNT_BY_DATE | 특정 시점까지 금액 목표 달성 |

### 주요 정보

| 항목        | 설명        |
| ----------- | ----------- |
| id          | 목표 식별자 |
| type        | 목표 유형   |
| targetValue | 목표값      |
| targetDate  | 목표일      |
| status      | 목표 상태   |

### 상태

- ACTIVE
- ACHIEVED
- PAUSED
- CANCELLED

### 규칙

- 목표값의 단위는 목표 유형과 일치해야 한다.
- 금액 목표에는 통화가 있어야 한다.
- 목표 자산배분은 자산 유형별 비율로 구성한다.
- 주택자금, 은퇴자금, 결혼자금 같은 목적성 금액 목표는 `TARGET_AMOUNT_BY_DATE`로 표현한다.
- AI가 사용자의 목표값을 임의로 변경할 수 없다.
- 목표 달성 여부는 결정론적인 계산 결과로 판단한다.

---

## 9. Snapshot

### 정의

특정 기간의 재무 상태와 분석 결과를 그대로 보존한 기록이다.

현재 재무 상태와 달리 Snapshot은 생성 이후 변경하지 않는다.

### 포함 정보

```text
Snapshot
 ├── Profile 기준값
 ├── Assets
 ├── Liabilities
 ├── MonthlyCashFlow
 ├── FinancialGoals
 ├── FinancialMetrics
 ├── FinancialWarnings
 └── RecommendationOptions
```

### 주요 정보

| 항목                  | 설명                  |
| --------------------- | --------------------- |
| id                    | 스냅샷 식별자         |
| period                | 분석 기간             |
| capturedAt            | 생성 시각             |
| financialState        | 해당 시점의 재무 상태 |
| metrics               | 계산된 재무 지표      |
| warnings              | 규칙 엔진 결과        |
| recommendationOptions | 규칙 기반 추천안 목록 |
| calculationVersion    | 계산 규칙 버전        |
| ruleSetVersion        | 경고 규칙 버전        |

### 규칙

- 스냅샷은 생성 이후 수정하지 않는다.
- 현재 데이터를 수정해도 기존 스냅샷에는 영향을 주지 않는다.
- 스냅샷 생성 당시의 프로필 기준을 함께 보존한다.
- 계산 결과와 규칙 결과의 버전을 기록한다.
- 같은 기간의 스냅샷을 자동으로 덮어쓰지 않는다.
- 같은 기간에 여러 스냅샷이 있으면 파일명이나 식별자에 `snapshotId`를 포함한다.
- 기존 스냅샷을 교체하려면 명시적인 사용자 동작이 필요하다.
- AI 보고서 본문은 스냅샷에 포함하지 않고 `ReviewReport`가 스냅샷을 참조한다.

## 10. FinancialMetric

### 정의

재무 데이터를 기반으로 계산된 개별 재무 지표다.

### 주요 지표

| 지표                  | 설명                  |
| --------------------- | --------------------- |
| TOTAL_ASSETS          | 총자산                |
| TOTAL_LIABILITIES     | 총부채                |
| NET_WORTH             | 순자산                |
| SAVINGS_RATE          | 월 저축률             |
| EMERGENCY_FUND_MONTHS | 비상자금 충당 개월 수 |
| DEBT_RATIO            | 부채 비율             |
| ASSET_ALLOCATION      | 자산배분              |
| ASSET_CONCENTRATION   | 자산 집중도           |
| TARGET_DEVIATION      | 목표 자산배분 이탈    |

### 주요 정보

| 항목               | 설명           |
| ------------------ | -------------- |
| type               | 지표 유형      |
| status             | 계산 상태      |
| value              | 계산 결과      |
| unit               | 결과 단위      |
| calculatedAt       | 계산 시각      |
| calculationVersion | 계산 규칙 버전 |

### 계산 상태

- CALCULATED
- INSUFFICIENT_DATA
- INVALID_INPUT
- NOT_APPLICABLE

### 규칙

- 계산할 수 없는 값을 0으로 표시하지 않는다.
- 계산 결과에는 단위가 있어야 한다.
- 계산에 사용한 기준일과 계산 버전을 추적할 수 있어야 한다.
- AI가 계산 결과를 수정할 수 없다.

구체적인 계산 공식은 `04-FINANCIAL-CALCULATIONS.md`에서 정의한다.

## 11. FinancialWarning

### 정의

규칙 엔진이 재무 상태에서 발견한 확인 필요 항목이다.

FinancialWarning은 투자 명령이 아니라 사용자가 검토해야 할 상태를 나타낸다.

### 경고 예시

- 비상자금 부족
- 특정 투자상품 집중
- 목표 자산배분 이탈
- 저축률 하락
- 고금리 부채 보유

### 주요 정보

| 항목        | 설명        |
| ----------- | ----------- |
| ruleId      | 실행한 규칙 |
| status      | 평가 결과   |
| severity    | 중요도      |
| evidence    | 판단 근거   |
| evaluatedAt | 평가 시각   |
| ruleVersion | 규칙 버전   |

### 평가 상태

- TRIGGERED
- NOT_TRIGGERED
- NOT_EVALUATED

### 중요도

- INFO
- LOW
- MEDIUM
- HIGH

### 규칙

- 경고는 명시적인 규칙 엔진에서 생성한다.
- 경고에는 실제값과 기준값 등 판단 근거가 있어야 한다.
- 데이터가 부족하면 `NOT_EVALUATED`로 처리한다.
- AI가 새로운 경고를 확정적으로 생성할 수 없다.
- 경고의 구체적인 조건은 `05-RULE-ENGINE.md`에서 정의한다.

## 12. PeriodComparison

### 정의

현재 스냅샷과 이전 스냅샷 사이의 변화를 나타낸다.

### 비교 대상

- 순자산
- 총자산
- 총부채
- 저축률
- 자산배분
- 비상자금
- 목표 진행률
- 경고 상태

### 변화 유형

| 유형                    | 설명              |
| ----------------------- | ----------------- |
| AMOUNT_CHANGE           | 금액 변화         |
| RATIO_CHANGE            | 비율 변화         |
| PERCENTAGE_POINT_CHANGE | 퍼센트포인트 변화 |
| STATUS_CHANGE           | 상태 변화         |
| NOT_COMPARABLE          | 비교 불가         |

### 경고 변화

- 새로 발생한 경고
- 해소된 경고
- 계속 유지되는 경고
- 평가할 수 없게 된 경고

### 규칙

- 비교할 이전 스냅샷이 없으면 최초 스냅샷 상태로 처리한다.
- 금액 변화와 비율 변화를 구분한다.
- 비교 불가능한 데이터는 이유를 표시한다.
- 이전 스냅샷 자체를 수정하지 않는다.

## 13. RecommendationOption

### 정의

애플리케이션 규칙과 템플릿으로 생성한 검토 가능한 재무 전략 선택지다.

RecommendationOption은 자동 실행 지시가 아니며, AI가 임의로 새로 생성하지 않는다.

### 주요 정보

| 항목 | 설명 |
| ---- | ---- |
| optionId | 추천안 식별자 |
| recommendationVersion | 추천 생성 규칙 버전 |
| templateVersion | 추천 템플릿 버전 |
| title | 추천안 이름 |
| strategy | 핵심 전략 |
| targetGoals | 우선적으로 고려한 목표 |
| rationale | 추천 근거 |
| requiredActions | 사용자가 검토할 행동 |
| expectedBenefits | 기대할 수 있는 효과 |
| tradeoffs | 단점과 포기해야 할 요소 |
| risks | 주의해야 할 위험 |
| constraints | 반영한 사용자 조건 |
| affectedMetrics | 영향을 받을 재무 지표 |

### 규칙

- 추천안은 계산 결과와 규칙 경고를 근거로 생성한다.
- 입력 데이터에 없는 금액, 수익률, 확률을 만들지 않는다.
- 직접적인 매수·매도 명령을 포함하지 않는다.
- 사용자가 선택하지 않은 추천안도 분석 세션 기록에 포함할 수 있다.
- 추천안 생성 규칙과 템플릿은 버전으로 관리한다.

## 14. ReviewReport

### 정의

스냅샷, 계산 결과, 기간 비교, 경고 결과를 기반으로 AI가 생성한 설명이다.

ReviewReport는 분석 결과를 설명하지만 원본 계산 결과를 변경하지 않는다.
ReviewReport는 스냅샷 저장 이후 생성되며, `snapshotId`로 기준 스냅샷을 참조한다.

### 주요 내용

- 이번 기간 결론
- 주요 변화
- 긍정적인 변화
- 주의할 항목
- 목표 진행 상황
- 다음 기간 확인 항목
- 판단할 수 없는 항목

### 주요 정보

| 항목          | 설명                 |
| ------------- | -------------------- |
| id            | 보고서 식별자        |
| snapshotId    | 기준 스냅샷          |
| status        | 생성 상태            |
| generatedAt   | 생성 시각            |
| model         | 사용한 AI 모델       |
| promptVersion | 프롬프트 버전        |
| content       | 구조화된 보고서 내용 |

### 상태

- GENERATED
- FAILED
- INVALID
- NOT_REQUESTED

### 규칙

- 보고서는 스냅샷 없이 생성할 수 없다.
- 보고서가 계산 결과를 변경해서는 안 된다.
- 입력 데이터에 없는 수치를 생성해서는 안 된다.
- 직접적인 매수·매도 명령을 포함해서는 안 된다.
- 보고서 생성 실패가 재무 계산 결과에 영향을 주어서는 안 된다.
- AI 관련 세부 규칙은 `06-AI-REPORT.md`에서 정의한다.

## 16. 핵심 도메인 규칙

1. 현재 재무 상태와 과거 스냅샷을 분리한다.
2. 생성된 스냅샷은 기본적으로 변경하지 않는다.
3. 모든 금액은 통화와 함께 관리한다.
4. 서로 다른 통화를 환율 없이 합산하지 않는다.
5. 계산할 수 없는 값을 임의로 0으로 대체하지 않는다.
6. 재무 지표는 애플리케이션 코드로 계산한다.
7. 경고는 명시적인 규칙 엔진에서 생성한다.
8. AI는 계산 결과와 경고를 설명하는 역할만 담당한다.
9. AI 실패가 계산과 경고 결과에 영향을 주지 않는다.
10. 과거 결과를 재현할 수 있도록 계산 및 규칙 버전을 기록한다.

## 17. MVP에서 제외하는 모델

초기 버전에서는 다음 모델을 별도로 만들지 않는다.

- 은행 계좌
- 증권 계좌
- 카드
- 개별 거래 내역
- 주문 및 체결
- 배당 내역
- 세금
- 사용자 인증
- 다중 사용자
- 금융기관 연동 정보

필요해질 때 기존 모델에 억지로 포함하지 않고 별도 명세를 작성한 후 추가한다.
