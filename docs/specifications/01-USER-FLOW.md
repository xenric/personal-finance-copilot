# User Flow Specification

## 1. 문서 목적

이 문서는 Personal Finance Copilot의 핵심 사용자 흐름과 각 단계의 입력, 처리, 출력 및 예외 상황을 정의한다.

전체 사용 흐름은 다음과 같다.

1. 사용자 등록 및 투자 목표 설정
2. 투자 성향 확인
3. 현재 재무 상태 입력
4. 재무 상태 분석
5. 복수 추천안 생성 및 검토
6. 필요 시 추가 조건을 반영한 재분석
7. 추천안 선택
8. 스냅샷 저장

전체 흐름의 시각적 표현은 `02-FLOW-CHART.md`에서 정의한다.

---

## 2. 핵심 원칙

- 재무 분석과 추천을 분리한다.
- 재무 수치는 결정론적인 애플리케이션 코드로 계산한다.
- AI는 계산 결과를 해석하고 여러 선택지를 설명한다.
- 추천은 자동으로 실행되지 않는다.
- 사용자는 추천안을 선택하지 않을 수 있다.
- 추천안이 만족스럽지 않으면 추가 조건을 입력해 다시 분석할 수 있다.
- 스냅샷에는 입력부터 최종 선택까지의 분석 과정을 저장한다.

---

## 3. 사용자 등록 및 투자 목표 설정

### 목적

사용자를 식별하고 재무 분석에 필요한 기본 정보와 투자 목표를 설정한다.

초기 MVP에서는 복잡한 인증 시스템 없이 로컬 사용자 프로필을 생성한다.

### 기본 사용자 정보

| 항목                  | 설명                         | 필수 여부 |
| --------------------- | ---------------------------- | --------: |
| 사용자 이름           | 화면에 표시할 이름           |      필수 |
| 기준 통화             | 분석 결과를 표시할 기준 통화 |      필수 |
| 출생 연도 또는 연령대 | 투자 기간 판단에 참고        |      선택 |
| 직업 또는 소득 형태   | 소득 안정성 분석에 참고      |      선택 |
| 가족 구성             | 향후 지출과 목표 분석에 참고 |      선택 |

### 투자 목표

사용자는 등록 과정에서 하나 이상의 투자 목표를 설정할 수 있다.

| 목표 유형   | 예시                             |
| ----------- | -------------------------------- |
| 순자산 목표 | 10년 후 순자산 10억 원           |
| 주택자금    | 5년 이내 주택 계약금 마련        |
| 비상자금    | 월 생활비 6개월분 확보           |
| 은퇴자금    | 장기 은퇴자금 마련               |
| 부채 감소   | 3년 이내 신용대출 상환           |
| 자산배분    | 주식·채권·금·현금 목표 비중 유지 |
| 특정 지출   | 결혼, 출산, 차량, 여행 비용 마련 |

### 투자 목표별 입력

| 항목                     | 설명                          | 필수 여부 |
| ------------------------ | ----------------------------- | --------: |
| 목표 이름                | 사용자가 식별할 이름          |      필수 |
| 목표 유형                | 순자산, 주택자금, 비상자금 등 |      필수 |
| 목표 금액 또는 목표 비율 | 목표 유형에 따른 값           |      필수 |
| 목표 시점                | 목표 달성 희망 시점           |      필수 |
| 우선순위                 | 여러 목표가 충돌할 때 사용    |      필수 |
| 월 투입 가능 금액        | 목표에 정기적으로 배분할 금액 |      선택 |
| 메모                     | 목표의 배경이나 추가 정보     |      선택 |

### 목표 우선순위

초기에는 다음 세 단계로 관리한다.

- HIGH
- MEDIUM
- LOW

동일한 우선순위의 목표가 서로 충돌할 경우 시스템은 임의로 하나를 선택하지 않고 사용자에게 충돌 사실을 보여준다.

### 처리

1. 사용자 기본 정보를 검증한다.
2. 기준 통화를 설정한다.
3. 하나 이상의 투자 목표를 등록한다.
4. 목표 금액, 기간, 우선순위를 검증한다.
5. 사용자 프로필과 투자 목표를 저장한다.

### 출력

- 사용자 프로필
- 등록된 투자 목표
- 목표별 기간과 우선순위
- 누락되거나 충돌하는 목표 정보
- 다음 단계 안내

### 예외

- 사용자 이름 누락
- 지원하지 않는 기준 통화
- 목표값 단위 오류
- 목표일이 현재보다 이전
- 목표 금액이 음수
- 목표 자산배분 합계 오류
- 서로 동시에 충족할 수 없는 목표

### 완료 조건

- 사용자 프로필이 생성된다.
- 기준 통화가 설정된다.
- 최소 하나의 투자 목표가 저장된다.
- 목표 금액, 기간, 우선순위가 유효하다.
- 사용자 데이터가 로컬 파일에 저장된다.

---

## 4. 투자 성향 확인

### 목적

사용자의 손실 감수 수준, 투자 기간, 유동성 요구와 투자 경험을 확인한다.

투자 성향 결과는 추천 생성 시 제약 조건으로 사용한다.

### 질문 영역

| 영역        | 확인 내용                               |
| ----------- | --------------------------------------- |
| 투자 기간   | 투자자금을 유지할 수 있는 기간          |
| 손실 감수   | 일시적인 평가손실을 감당할 수 있는 수준 |
| 투자 경험   | 주식, ETF, 채권 등의 투자 경험          |
| 유동성      | 가까운 시기에 필요한 자금 규모          |
| 안정성 선호 | 안정성과 기대수익 중 우선하는 요소      |
| 하락장 대응 | 시장 하락 시 예상 행동                  |
| 소득 안정성 | 정기 소득의 안정성                      |
| 목표 중요도 | 투자 목표별 중요도와 조정 가능성        |

### 투자 성향 결과

MVP에서는 다음 세 단계로 구분한다.

| 유형         | 설명                             |
| ------------ | -------------------------------- |
| CONSERVATIVE | 안정성과 유동성을 우선           |
| BALANCED     | 안정성과 장기 성장의 균형을 우선 |
| GROWTH       | 장기 성장과 변동성 감수를 우선   |

### 처리

1. 필수 질문에 대한 응답을 수집한다.
2. 점수 기반 규칙으로 투자 성향을 계산한다.
3. 사용자에게 결과와 판단 근거를 보여준다.
4. 사용자가 결과를 확인한다.
5. 검사 결과와 검사 버전을 저장한다.

### 규칙

- AI가 투자 성향을 임의로 결정하지 않는다.
- 성향 산정 기준은 명시적인 규칙으로 관리한다.
- 사용자가 결과를 확인하거나 다시 검사할 수 있어야 한다.
- 투자 성향과 투자 목표는 별도로 관리한다.
- 투자 성향이 목표 달성을 보장하지 않는다.

### 완료 조건

- 모든 필수 질문에 답변한다.
- 투자 성향 결과가 계산된다.
- 사용자가 결과를 확인한다.
- 검사 결과와 버전이 저장된다.

---

## 5. 현재 재무 상태 입력

### 목적

재무 분석에 필요한 현재 자산, 부채, 소득, 지출과 투자 상태를 입력한다.

### 소득과 지출

| 항목              | 설명                           |
| ----------------- | ------------------------------ |
| 월 소득           | 세후 기준 월평균 소득          |
| 월 고정지출       | 주거비, 보험료, 통신비 등      |
| 월 변동지출       | 식비, 여가비 등                |
| 월 부채 상환액    | 대출 및 부채 상환액            |
| 월 투자 가능 금액 | 정기적으로 투자할 수 있는 금액 |

### 자산

| 자산 유형     | 예시                    |
| ------------- | ----------------------- |
| 현금성 자산   | 현금, CMA, 예금         |
| 국내 투자자산 | 국내 주식, 국내 ETF     |
| 해외 투자자산 | 해외 주식, 해외 ETF     |
| 안전자산      | 채권, 금                |
| 실물자산      | 부동산, 차량            |
| 기타 자산     | 별도 분류가 필요한 자산 |

### 부채

| 항목      | 설명                      |
| --------- | ------------------------- |
| 부채 유형 | 주택담보대출, 신용대출 등 |
| 현재 잔액 | 남은 상환 금액            |
| 적용 금리 | 현재 적용 금리            |
| 월 상환액 | 정기 상환 금액            |
| 만기일    | 상환 만기                 |

### 투자자산 추가 정보

| 항목          | 설명                       |
| ------------- | -------------------------- |
| 상품명        | 사용자에게 표시할 이름     |
| 상품 유형     | 주식, ETF, 채권, 금 등     |
| 평가금액      | 현재 평가된 금액           |
| 통화          | KRW, USD 등                |
| 평가 기준일   | 가격이 평가된 날짜         |
| 평균 매입금액 | 선택 입력                  |
| 자산군        | 주식, 채권, 현금성 자산 등 |

### 데이터 검증

분석 전에 다음을 확인한다.

- 필수값이 모두 존재하는가?
- 금액과 통화가 유효한가?
- 음수가 허용되지 않는 값에 음수가 입력되었는가?
- 동일한 자산이 중복 등록되었는가?
- 부채 잔액과 금리가 유효한가?
- 해외자산 계산에 필요한 환율이 존재하는가?
- 평가금액에 기준일이 존재하는가?
- 사용자 목표와 현재 데이터의 단위가 일치하는가?

### 데이터가 부족한 경우

필수 데이터가 부족하면 분석을 진행하지 않는다.

사용자에게 다음 정보를 제공한다.

- 누락된 항목
- 잘못 입력된 항목
- 분석에 필요한 이유
- 수정해야 할 위치

## 6. 재무 상태 분석

### 목적

현재 재무 상태와 등록된 투자 목표를 기준으로 재무 지표를 계산하고 위험 또는 목표 이탈을 확인한다.

AI는 재무 수치를 계산하지 않는다.

### 재무 상태 분석

- 총자산
- 총부채
- 순자산
- 월 저축액
- 월 저축률
- 비상자금 충당 개월 수
- 부채 비율
- 고금리 부채 비중

### 투자 구성 분석

- 전체 투자자산
- 자산군별 비중
- 국내·해외 투자 비중
- 위험자산·안전자산 비중
- 단일 상품 집중도
- 특정 자산군 집중도
- 투자 성향과 현재 구성의 차이

### 목표 분석

각 투자 목표에 대해 다음을 계산한다.

- 현재 달성 금액 또는 비율
- 목표까지 남은 금액
- 목표일까지 남은 기간
- 현재 진행률
- 월별 필요 적립액
- 목표 달성 가능성을 판단하기 위해 부족한 정보
- 여러 목표 사이의 자금 배분 충돌

### 규칙 기반 경고

- 비상자금 부족
- 높은 부채 비율
- 고금리 부채 보유
- 특정 상품 집중
- 목표 자산배분 이탈
- 투자 성향과 현재 자산구성 불일치
- 단기 목표 자금의 과도한 위험자산 편입
- 목표 대비 월 투자 가능 금액 부족
- 필요한 데이터 부족

### 분석 결과

분석 결과는 다음 영역으로 구분한다.

1. 현재 재무 상태
2. 투자 구성
3. 부채 및 현금흐름
4. 목표별 진행 상황
5. 규칙 기반 경고
6. 분석할 수 없는 항목
7. 추천 생성에 사용할 근거

### 완료 조건

- 계산 가능한 지표가 생성된다.
- 목표별 진행률이 계산된다.
- 계산 불가 항목에는 이유가 표시된다.
- 규칙 기반 경고가 생성된다.
- 계산 결과와 AI 설명이 분리된다.
- 복수 추천 생성에 필요한 구조화 데이터가 준비된다.

## 7. 복수 추천안 생성

### 목적

하나의 정답을 제시하지 않고, 서로 다른 우선순위와 장단점을 가진 여러 선택지를 제공한다.

추천안은 자동매매 지시가 아니라 사용자가 검토할 수 있는 재무 전략이다.

### 기본 추천 유형

MVP에서는 최대 세 개의 추천안을 제공한다.

#### 안정 우선안

- 비상자금 확보
- 고금리 부채 상환
- 현금성 자산 유지
- 단기 목표자금 보호
- 자산 변동성 완화

#### 균형안

- 비상자금과 투자 병행
- 부채 상환과 장기 투자 균형
- 목표 자산배분 유지
- 복수 목표에 대한 균형 배분

#### 성장 우선안

- 장기 투자 비중 확대
- 높은 변동성 감수
- 장기 순자산 목표 우선
- 단기 유동성보다 성장성 우선

모든 추천 유형을 반드시 생성할 필요는 없다. 사용자 조건과 맞지 않는 유형은 제외할 수 있다.

### 추천안 구성

| 항목             | 설명                        |
| ---------------- | --------------------------- |
| optionId         | 추천안 식별자               |
| title            | 추천안 이름                 |
| strategy         | 핵심 전략                   |
| targetGoals      | 우선적으로 고려한 투자 목표 |
| rationale        | 추천 근거                   |
| requiredActions  | 사용자가 검토할 행동        |
| expectedBenefits | 기대할 수 있는 효과         |
| tradeoffs        | 단점과 포기해야 할 요소     |
| risks            | 주의해야 할 위험            |
| constraints      | 반영한 사용자 조건          |
| affectedMetrics  | 영향을 받을 재무 지표       |

### 추천 생성 규칙

- 기본적으로 2~3개의 추천안을 제공한다.
- 추천안마다 우선순위와 장단점이 달라야 한다.
- 같은 내용을 이름만 바꿔 반복하지 않는다.
- 사용자의 투자 성향을 반영한다.
- 사용자가 등록한 투자 목표와 우선순위를 반영한다.
- 단기 목표와 장기 목표의 충돌을 표시한다.
- 계산 결과와 규칙 경고를 추천 근거로 연결한다.
- 입력에 없는 금액이나 수익률을 생성하지 않는다.
- 직접적인 매수·매도 명령을 제공하지 않는다.
- 추천이 사용자의 모든 목표를 동시에 충족하지 못하면 그 사실을 표시한다.

---

## 8. 추천안 검토

사용자는 추천안을 비교한 후 다음 행동 중 하나를 선택한다.

1. 추천안 선택
2. 추가 조건을 입력하고 재분석
3. 현재 재무 데이터 수정
4. 추천 없이 분석 결과만 저장
5. 추천 결정을 보류하고 저장
6. 분석 종료

### 비교 기준

- 투자 성향 적합성
- 우선 투자 목표 달성 기여도
- 단기 유동성
- 부채 감소 효과
- 예상 변동성
- 실행 난이도
- 필요한 월 현금흐름
- 기존 자산 매도 필요 여부
- 다른 목표에 미치는 영향
- 사용자가 포기해야 하는 요소

---

## 9. 추가 조건 입력 및 재분석

### 목적

추천안이 사용자의 실제 상황이나 선호를 충분히 반영하지 못한 경우 추가 조건을 입력해 새로운 추천안을 생성한다.

### 추가 조건 유형

#### 목표 조건

- 주택 마련 목표를 최우선으로 변경
- 순자산 목표 기간 연장
- 비상자금 목표를 먼저 달성
- 일부 목표를 일시 중지
- 목표별 월 배분 한도 설정

#### 자금 사용 계획

- 결혼 비용
- 주택 구입
- 차량 구매
- 출산 및 육아
- 여행 및 대형 지출
- 부모 지원

#### 투자 조건

- 특정 자산은 매도하지 않음
- 신규 투자금으로만 조정
- 해외자산 비중 제한
- 주식 비중 상한 설정
- 현금 비중 하한 설정
- 특정 상품 또는 산업 제외

#### 실행 조건

- 월 투자 가능 금액 제한
- 실행 단계를 3개 이하로 제한
- 기존 보유자산 매도 최소화
- 세금과 수수료가 큰 변경 제외
- 월 1회만 관리

### 처리

1. 추가 조건의 형식과 단위를 검증한다.
2. 기존 조건과 충돌하는지 확인한다.
3. 충돌이 없다면 기존 재무 데이터와 결합한다.
4. 추가 조건에 영향을 받는 부분을 다시 분석한다.
5. 새로운 복수 추천안을 생성한다.
6. 사용자가 다시 추천안을 평가한다.

### 재분석 범위

다음 값은 원본 데이터가 변경되지 않았다면 다시 계산하지 않을 수 있다.

- 총자산
- 총부채
- 순자산
- 현재 자산배분
- 현재 부채 비율

다음 항목은 추가 조건에 따라 다시 평가한다.

- 목표 우선순위
- 목표별 자금 배분
- 목표 달성 전략
- 추천안
- 추천안의 장단점
- 조건 충돌 여부

### 조건 충돌

충돌하는 조건을 임의로 무시하거나 우선순위를 결정하지 않는다.

예시:

```text
조건 1: 현금 비중을 최소 30%로 유지
조건 2: 투자자산 비중을 최소 85%로 유지

결과: 두 조건을 동시에 충족할 수 없음
```

사용자에게 다음을 요청한다.

- 우선할 조건 선택
- 조건값 완화
- 특정 목표의 기간 조정
- 목표 우선순위 변경

### 반복 종료 조건

재분석은 다음 상황에서 종료한다.

- 사용자가 추천안을 선택함
- 분석만 저장함
- 추천 결정을 보류함
- 사용자가 분석을 종료함
- 충돌 조건을 해결하지 못함
- 시스템에서 설정한 최대 재분석 횟수에 도달함

MVP에서는 무한 반복을 방지하기 위해 분석 세션별 최대 재분석 횟수를 설정할 수 있다.

---

## 10. 추천안 선택

### 목적

사용자가 자신에게 가장 적합하다고 판단한 추천 전략을 기록한다.

추천안 선택은 실제 금융 거래 실행을 의미하지 않는다.

### 저장 정보

| 항목                  | 설명                      |
| --------------------- | ------------------------- |
| selectedOptionId      | 선택한 추천안             |
| selectedAt            | 선택 시각                 |
| userReason            | 선택 이유                 |
| appliedConditions     | 적용된 추가 조건          |
| prioritizedGoals      | 해당 추천에서 우선한 목표 |
| recommendationVersion | 추천 버전                 |

### 규칙

- 선택한 추천안을 자동으로 실행하지 않는다.
- 사용자는 추천안을 선택하지 않을 수 있다.
- 실제 실행 여부는 다음 분석에서 별도로 확인한다.
- 선택하지 않은 추천안도 해당 분석 세션 기록에 포함할 수 있다.
- 선택된 추천안이 사용자의 목표 자체를 변경하지 않는다.

## 11. 스냅샷 저장

### 목적

특정 시점의 사용자 입력, 분석 결과, 추천 과정과 사용자 결정을 재현할 수 있도록 저장한다.

### 저장 대상

- 사용자 프로필 기준값
- 등록된 투자 목표와 우선순위
- 투자 성향 검사 결과와 버전
- 현재 자산·부채·소득·지출
- 재무 계산 결과
- 목표별 진행 상황
- 규칙 기반 경고
- 추가 조건
- 최초 추천안
- 재분석 결과
- 최종 추천안
- 선택한 추천안 또는 미선택 상태
- AI 보고서 생성 결과
- 계산·규칙·프롬프트 버전

### 스냅샷 상태

| 상태                     | 설명                |
| ------------------------ | ------------------- |
| ANALYSIS_ONLY            | 분석 결과만 저장    |
| RECOMMENDATION_PENDING   | 추천 검토 중        |
| RECOMMENDATION_SELECTED  | 추천안 선택 완료    |
| CLOSED_WITHOUT_SELECTION | 추천 선택 없이 종료 |

### 저장 규칙

- 스냅샷은 생성 이후 기본적으로 수정하지 않는다.
- 현재 데이터 변경이 기존 스냅샷을 변경하지 않는다.
- 추천을 선택하지 않아도 저장할 수 있다.
- AI 추천 생성이 실패해도 분석 결과를 저장할 수 있다.
- 재분석 과정과 적용 조건을 추적할 수 있어야 한다.
- 같은 기간의 스냅샷을 자동으로 덮어쓰지 않는다.

## 13. MVP 범위

초기 버전에서는 다음 흐름까지만 구현한다.

1. 로컬 사용자 프로필 생성
2. 사용자 등록 과정에서 투자 목표 입력
3. 3단계 투자 성향 검사
4. 자산·부채·소득·지출 입력
5. 재무 지표와 목표 진행률 계산
6. 규칙 기반 경고 생성
7. 2~3개의 추천안 생성
8. 추가 조건을 반영한 재분석
9. 추천안 선택 또는 분석만 저장
10. 월간 스냅샷 저장

초기 버전에서는 다음을 제외한다.

- 복수 사용자 로그인
- 금융기관 자동 연동
- 추천안 자동 실행
- 실시간 종목 추천
- 조건 충돌 자동 최적화
- 거래 단위 실행 계획
- 추천 성과의 자동 추적
