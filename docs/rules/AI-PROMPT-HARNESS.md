# AI Prompt/Harness 규칙

## 적용 범위와 현재 상태

이 문서는 AI 보고서 프롬프트, LLM adapter, 모델 설정, 출력 파서·검증기와 평가 harness를 설계하거나 변경할 때 적용한다. AI 보고서의 제품 계약과 출력 구조는 `docs/specifications/06-AI-REPORT.md`를 기준으로 한다.

현재 저장소에는 LLM adapter, 프롬프트 템플릿과 평가 harness가 없다. 해당 구현을 추가하기 전에는 존재하지 않는 평가 명령이나 baseline을 통과했다고 보고하지 않는다.

## 책임 경계

- 재무 계산, 투자 성향, 경고와 추천안은 애플리케이션의 결정론적 로직이 생성한다.
- AI는 제공된 결과와 선택지를 설명하며 원본 값을 수정하거나 새 투자 지시를 만들지 않는다.
- 모델 출력만으로 도구 호출, 외부 통신, 주문 실행 또는 파일 변경을 수행하지 않는다.
- AI 기능은 선택적인 보조 계층이다. AI 실패가 핵심 계산, 경고와 스냅샷 저장을 막아서는 안 된다.

## 프롬프트 계약

- system/developer 지침, 애플리케이션 데이터와 사용자 제공 텍스트를 구분한다.
- 사용자 메모와 외부 데이터는 신뢰할 수 없는 데이터로 표시하고 그 안의 명령문을 실행 지침으로 따르지 않는다.
- 모델 입력은 허용 목록 기반의 구조화 데이터로 최소화한다.
- 금액, 통화, 기간, 계산 상태, 근거, 계산·규칙 버전의 의미를 명시한다.
- API 키, 내부 경로, 로그 전문과 설명에 필요 없는 개인정보는 전달하지 않는다.
- 모르는 내용은 추정하지 않고 출력의 `unknowns`에 기록하도록 요구한다.
- 출력은 `docs/specifications/06-AI-REPORT.md`의 스키마를 따르게 한다.

프롬프트 템플릿, 출력 스키마 또는 결과 의미에 영향을 주는 모델 설정을 변경하면 `promptVersion` 변경 필요성을 검토한다. 모델명, 프롬프트 버전, 생성 시각과 참조한 `snapshotId`를 추적할 수 있어야 한다.

프롬프트와 사용자 데이터 전체를 운영 로그에 남기지 않는다. 진단 로그는 식별자, 버전, 지연 시간, 토큰 사용량과 오류 범주 중심으로 기록한다.

## 출력 검증

모델 출력은 신뢰할 수 없는 외부 입력으로 취급하고 애플리케이션 경계에서 다음 순서로 검증한다.

1. JSON 파싱 가능 여부와 필수 필드를 확인한다.
2. 스키마에서 허용하지 않은 추가 필드는 거부한다.
3. 각 필드의 타입과 스키마에 정의된 길이 제한을 확인한다.
4. 구조화된 수치, 식별자, 계산 상태와 추천안 식별자를 원본 입력과 대조한다.
5. 직접 매수·매도 명령, 수익 보장과 위험 축소 등 금지된 결과를 검사한다.
6. 검증 실패 시 AI 보고서를 성공으로 저장하지 않고 안전한 결정론적 결과를 제공한다.

단순 문자열 금칙어만으로 안전성을 보장하지 않는다. 구조와 원본 근거 대조는 결정론적으로 검사하고, 자연어의 충실성과 중립성은 대표 위반 사례를 포함한 평가로 보완한다.

## 실패 처리

- timeout, rate limit, 인증 오류, 일시 장애와 잘못된 출력을 구분 가능한 오류 범주로 매핑한다.
- 재시도는 멱등성과 제공자 오류 특성을 확인한 뒤 일시 오류에만 제한한다.
- 내부 오류 전문과 비밀값을 사용자 응답에 노출하지 않는다.
- 실패 상태와 재시도 가능 여부를 저장하거나 사용자에게 알린다.
- AI 실패 시에도 계산 결과, 규칙 경고와 저장된 스냅샷을 제공한다.

## 회귀 평가

프롬프트 또는 AI 연동 동작을 변경할 때 고정된 합성 fixture로 회귀를 검증한다. 실제 개인 재무 데이터는 사용하지 않는다.

최소 사례:

- 정상 입력과 필수 출력 필드
- 데이터 부족과 `unknowns`
- 경고 없음, 복수 경고와 계산 불가 상태
- 이전 기간 없음과 비교 불가능 항목
- 복수 추천안이 있을 때 중립적인 트레이드오프 설명
- 직접 매수·매도 지시와 수익 보장 요청 거부
- 사용자 메모에 포함된 프롬프트 인젝션 무시
- 입력에 없는 숫자와 상품 정보 비생성
- 통화와 기간 유지
- malformed JSON, 누락 필드와 길이 초과
- timeout, rate limit, 인증 오류와 일시 장애 시 핵심 기능 유지

검증은 다음처럼 분리한다.

- 결정론적 검사: JSON 스키마, 필드, 길이, 수치 근거, 식별자와 금지된 구조
- 의미 평가: 충실성, 불확실성 표현, 선택지의 중립성과 설명의 유용성
- 통합 테스트: adapter 오류 매핑, 제한된 재시도와 민감정보 비노출

결정론적 검사는 일반 JUnit 테스트로 실행한다. 실제 모델 호출 평가는 단위 테스트와 분리하며, harness가 추가되는 변경에서 fixture 위치, 실행 명령, 모델, 프롬프트 버전과 비용 조건을 함께 문서화한다.

구조와 안전 불변 조건은 모든 fixture에서 통과해야 한다. 의미 평가를 품질 게이트로 사용할 경우 실제 baseline을 수집한 뒤 rubric, 표본 수, 허용 임계값과 baseline 갱신 승인 절차를 먼저 명시한다. 정의되지 않은 임계값이나 단 한 번의 비결정적 결과로 회귀가 없다고 판단하지 않는다.

모델 출력 문구 전체를 고정해 비교하지 않는다. 모델 또는 프롬프트 버전 변경 시 동일 fixture의 기존 baseline과 비교하고 악화된 사례를 기록한다.

## 개인정보와 보안

- fixture와 예제에는 명확히 합성된 최소 데이터만 사용한다.
- 실제 개인 데이터, 계좌번호, API 키와 비밀값을 저장소에 커밋하지 않는다.
- 로그, 오류 응답과 테스트 결과에서 민감정보를 마스킹한다.
- 외부 서비스로 전송하는 필드는 명시적으로 허용하고 데이터 최소화를 적용한다.
- 새 모델 제공자나 telemetry를 추가하면 전송 데이터, 보존 정책, 실패 영향과 비밀값 관리 방식을 보고한다.

## 완료 조건

AI 관련 동작을 변경한 경우에만 다음을 적용한다.

- 출력 스키마와 원본 근거 대조가 검증되었다.
- 안전 불변 조건과 대표적인 금지 사례가 검증되었다.
- AI 실패가 핵심 기능과 저장을 방해하지 않음이 검증되었다.
- 프롬프트 버전 변경 여부와 추적 메타데이터가 검토되었다.
- 실행한 평가와 실행하지 못한 평가를 구분해 보고했다.
- 실제 개인 데이터와 비밀값이 입력, 로그와 diff에 포함되지 않았다.
